## 3. 多 AI 协作规范

### 3.1 规则与记忆的分层（重要，工具无关）

规则**正文只存一份**：根目录 `AGENTS.md`（跨 AI 工具事实标准）。各工具的加载情况：

| 工具 | 规则加载方式 | 说明 |
|---|---|---|
| WorkBuddy / CodeBuddy | 自动加载根目录 `AGENTS.md`（官方兼容），另有 `.codebuddy/rules/`、`.workbuddy/memory/` 记忆注入 | AGENTS.md 零配置生效 |
| Claude Code | 自动加载根目录 `CLAUDE.md` | 模板已提供 `CLAUDE.md`，内容仅一行 `@AGENTS.md` 引入 |
| ZCode | 自动加载 `AGENTS.md` 等约定路径 | 零配置 |
| opencode | 自动加载 `AGENTS.md` | 零配置 |
| Cursor / Codex / Gemini CLI | 原生支持 `AGENTS.md`（Cursor 也可用 `.cursor/rules/`） | 零配置或可选适配 |
| Trae | 自动加载 `.trae/rules/` | **无引入机制**：需复制 AGENTS.md 正文过去（此为唯一允许的复制场景，正文变更时需同步） |
| {{其他工具，如 dsh}} | 以其官方文档为准 | 若遵循 AGENTS.md 约定则零配置；若有专属路径且无引入机制，才复制正文 |

**去重铁律**：除 Trae 这类无引入机制的工具外，任何入口文件（CLAUDE.md 等）**禁止复制规则正文**，只允许一行引入——避免同一规则被多工具重复注入上下文、版本漂移。

**规则与记忆分离**：规则 = 强制指令（AGENTS.md，人工修订）；记忆 = 知识沉淀（`.workbuddy/memory/`，3000 字符限额，不承载规则）。

### 3.2 会话生命周期

- **开工**：读 doc/05 → 读 doc/会话交接.md → 交接板写「当前持有者」→ git pull
- **工作**：每次改动更新 CHANGELOG；排障写调试记录
- **收尾**：更新 doc/05 → 更新交接板并清空持有者 → commit + push

### 3.3 并发控制

同一时间只允许一个 AI 会话动工（以交接板「当前持有者」为准）。并行开发各自开 feature 分支，主线 main 只由持有者合并。

## 4. 质量与验证规范

### 4.1 修复落地验证（强制）

- CHANGELOG 记"已修复"前，必须 **Read 被修改文件**确认改动真实存在（不能只信编辑工具返回值）
- 运行时类修复必须**实际运行验证**，附真实证据；"语法检查通过"不算验证

### 4.2 修复验证方式对照表

| 修复类型 | 必须的验证方式 | 不充分的验证方式 |
|---|---|---|
| 纯逻辑 | 单测 / 静态追踪 | 仅肉眼看代码 |
| 进程/端口 | 实际启动 + 端口检查 | 仅语法检查 |
| HTTP API | 实际请求 | 仅语法检查 |
| 构建/部署 | 实际 build + 运行 | 仅看配置 |
| UI 交互 | 实际打开页面操作 | 仅 build 通过 |

### 4.3 回归预防

修复一处反模式后：① 检查其他文件有无同类问题；② 检查 CHANGELOG 有无"声称已修复但未验证落地"的同类条目。

## 5. 安全红线

- 凭据只进 `.env`（gitignored）；文档代码只写占位符
- 敏感数据不写入任何会外发的 prompt/请求体
- 禁止破坏性命令：`docker system prune -a`、裸路径递归删除、未经确认的批量删除
- 生产环境操作二次确认

## 6. 提交规范

- commit 格式：`<类型>: <摘要>`，类型 = feat/fix/docs/chore/refactor；中文摘要
- 每个逻辑单元一个 commit，不攒大包；推送前确认无凭据泄露
